== Design Decision Log

[[DEC-1]]
=== DEC-1: Reuse the existing domain service instead of a new store

*Status:* accepted

*Context:* Evidence shows an existing service already owns this data.

*Options considered:*

* Reuse existing service API
* New dedicated data store

*Decision:* Reuse existing service API

*Rationale:* Avoids dual writes; satisfies FR-1 with less change.

*Consequences:*

* Dependency on existing service availability

*Evidence:* <<EV-1>>, <<EV-2>>

[[DEC-2]]
=== DEC-2: Event-fed read model for display paths

*Status:* accepted

*Context:* Display traffic is read-heavy; commit path needs strong consistency.

*Options considered:*

* Synchronous reads everywhere
* CQRS read model fed by events

*Decision:* CQRS read model fed by events, synchronous validation at commit

*Rationale:* Meets NFR-1 without loading the system of record.

*Consequences:*

* Eventual consistency on display paths
* Needs replay on consumer lag

*Evidence:* <<EV-12>>

[[DEC-3]]
=== DEC-3: Introduce a new message broker

*Status:* accepted

*Context:* Events need transport.

*Options considered:*

* Use the existing platform broker
* New broker

*Decision:* New broker

*Rationale:* Isolation.

*Consequences:*

* Extra operational cost
